② 各ステップの詳細

🔤 Step 0: クエリベクトル化（両方共通）

項目値 / 説明
モデルbge-m3（1024次元）
処理内容Ollama Embedding API でクエリを数値ベクトルに変換
考え方bge-m3 は日本語に強く、多言語対応。1024次元で高精度な類似度計算が可能。

📐 / 🏷️ Step 1: ベクトル検索（Naive） vs メタデータフィルタ（Hybrid）

比較軸Naive RAGHybrid RAG
絞り込み方法類似度ベース Top-4tenant_id + effective_year でメタフィルタ
候補数15 → 4件15 → 8件（フィルタ後）
問題点別テナント・廃止規定が混入対象テナントの有効規定のみ抽出

💡 マルチテナント環境では、メタデータで事前に候補を絞り込むことが必須。Naive RAG は「類似度だけ」なので、意味的に近いけど無関係なドキュメント（別テナントの罠データ）が上位に来る。

🔑 Step 2: BM25 キーワードスコアリング（Hybrid RAGのみ）

項目値 / 説明
形態素解析Janome（名詞・動詞・形容詞を抽出）
スコアリングBM25Okapi（標準パラメータ k1=1.5, b=0.75）
抽出語数クエリから約 12 語（キャプチャ例）
考え方ベクトル検索は「意味の近さ」を捉えるが、キーワードの正確な一致を見逃すことがある。BM25 は逆文書頻度（IDF）で希少語に重み付けし、クエリの核心語を強く反映させる。

⚖️ Step 3: RRF 統合リランキング（Hybrid RAGのみ）

項目値 / 説明
式rrf = 1/(k+rank_vec) + 1/(k+rank_bm25)
k 値60（論文推奨デフォルト値）
統合結果vec(8件) + BM25(8件) → Top-3 選定
考え方Reciprocal Rank Fusion は2つのランキングを融合する単純ながら強力な手法。k=60 は上位順位に大きな重みを置きつつ、下位順位も無視しないバランスを実現。各チャンクには vec#N / bm25#N のラベルと rrf_score が付与され、追跡可能。

🧠 Step 4: LLM推論（両方共通）

項目値 / 説明
モデルgemma4:e4b
プロンプト長約 2000文字（参考情報＋質問＋フォーマット指示）
考え方選定されたチャンクをコンテキストとしてLLMに渡し、構造化回答を生成。Naive RAG と Hybrid RAG で同じモデル・同じプロンプトテンプレートを使用し、検索品質の差のみを比較可能にする。
